# AAC landscape and dependency options — October 2026

Prepared for **Voice** v1.2.0 (Expo SDK 54, React Native 0.81.5). All sources accessed **2026-10-03**.

**Method.** Claims come only from vendor product pages, vendor support/knowledge-base pages, vendor press releases, or the official documentation of a library or symbol set. Each row says where a fact came from. Where a capability is not mentioned on the pages checked, the doc says **"not found on official pages"**. That means only that it was not found. It does not mean the product lacks the feature. Marketing pages change often and can omit features, so re-check anything before quoting it externally.

**Notation.** **Fact (Sn)** is a claim from source Sn in the source list at the end of Part 1. **Inference** is the author's own reading and is not a vendor claim.

This doc makes no claims about market share or leadership. Visual design is described only in general terms. No layouts, branding or proprietary vocabularies are reproduced.

### 1.7 Visual design (general terms only)

- **Fact.** Vendors describe grid-based button layouts with configurable density, e.g. 9–144 buttons (S1) and 25–108 (S4).
- **Fact.** Products use colour coding: Avaz cites the Fitzgerald key (S6). They also use consistent motor patterns across vocabulary levels (S6, S3 "Motor Plan").
- **Fact.** Products offer attention-guiding aids: Proloquo's "Focus Mode" uses "light and motion" (S2).
- **Inference.** Across the category, the common approach is a stable spatial layout with progressive vocabulary disclosure. Visual identity differs by vendor and is not analysed here.

### 1.8 Opportunities for Voice — **all Inference**

Each opportunity below is the author's reading of the comparison above. None is a vendor claim or a validated user need.

1. **Offline-first, stated plainly.** Offline behaviour was not stated on most of the official pages checked. Voice could say clearly what works offline, for example the board, speech and on-device prediction, and what needs a network. ARASAAC pictogram search needs a network. A clear in-app indicator and cached core symbols would help.
2. **Transparent, on-device prediction.** Vendors that describe prediction (S6, S11, S13) do not, on the pages checked, explain *why* a word was suggested. Voice already has explainability and personalisation controls (`docs/ai/`). Keeping them on-device, and letting the user reset them, would set Voice apart without cloud AI.
3. **Low-cost Android coverage with sensory-friendly defaults.** Several of the products checked list Apple and/or Windows platforms only (S1, S2, S4, S11). Android coverage, together with reduced-motion and haptic options (see Part 2), could be offered at no cost. Partner and caregiver workflows (remote editing, reports) are a later-stage gap. They should not be built before core reliability.

Do not copy proprietary page sets, layouts, symbol libraries or trade names (WordPower, Core First, Crescendo, etc.).

## Part 2 — Dependency and asset options

Installed baseline, checked locally on 2026-10-03:
- `expo` 54.0.33, `react-native` 0.81.5, `newArchEnabled: true` (`app.json`).
- `@tensorflow/tfjs` 4.22.0 (other tfjs packages pinned at 4.16.0) and `@tensorflow/tfjs-react-native` 1.0.0.
- **`expo-haptics` is not installed**: `ls node_modules/expo-haptics` returns "No such file or directory". The SDK 54 bundled version in `node_modules/expo/bundledNativeModules.json` is `~15.0.8`.
- `src/` makes no reduced-motion API call: grep for `isReduceMotionEnabled` and `reduceMotionChanged` found nothing.

### 2a. Reduced-motion detection

| Option | Licence | Expo 54 | Size | Offline | iOS / Android |
|---|---|---|---|---|---|
| `AccessibilityInfo.isReduceMotionEnabled()` plus the `reduceMotionChanged` event (built into RN) | MIT (part of RN) | Yes, no new dependency | 0 | Yes | Both. On Android it also detects "Transition Animation Scale = off" (R1) |
| Third-party libraries | — | — | — | — | Not needed. No candidate adds anything over the built-in API |

**Recommendation: adopt now.** Use a small `useReducedMotion()` hook built on the RN API. If Reanimated is ever added, its own `useReducedMotion` is an alternative, but it is not worth adding Reanimated just for this.

### 2b. Haptics — `expo-haptics`

| Field | Finding |
|---|---|
| Licence | MIT (`npm view expo-haptics@15.0.8 license`; repo expo/expo) |
| Expo 54 compatibility | Documented for SDK 54 on Android, iOS and web; install with `npx expo install expo-haptics` (R2). Bundled version is `~15.0.8` |
| Native rebuild | **Yes for this app.** It is a native module, and Voice ships through `expo-dev-client` and EAS builds, so a new dev/production build is needed after installing it. Expo Go would not need one, but Voice does not rely on Expo Go. **Inference**: the docs page (R2) does not spell this out; it follows from how native modules work |
| Android permission | The library adds `VIBRATE` automatically (R2). This changes the merged manifest, so check the Play Data Safety and permissions notes |
| Size | ~80 KB unpacked on npm (JS and native) |
| Behaviour notes | iOS: no haptics in Low Power Mode, when disabled in settings, or while the camera or dictation is active (R2). Android: `performAndroidHapticsAsync()` is recommended (R2) |

**Recommendation: adopt in the next native build.** Make haptics opt-in or respect a user setting: some AAC users have sensory sensitivities (**Inference**).

### 2d. On-device next-word prediction

| Option | Licence / maintenance | Expo 54 / New Architecture | Size | Feasibility (Inference unless cited) |
|---|---|---|---|---|
| n-gram in plain JS (already partly present: bigrams in `src/services/aiProfileStore.js`) | Own code | Works today, no native code | A few KB to ~1 MB for a trigram table | **High.** Fast, explainable, works offline; vocabulary can come from a permissively licensed corpus |
| `@tensorflow/tfjs-react-native` (current) | Apache-2.0. **Last published 2023-11** (npm `time.modified`). Peer deps target `expo-gl ^13` and `expo-camera ^13`, while the app has v16 and v17 | Works in this app now, but outside its declared peer ranges | ~780 KB unpacked plus tfjs core | **Medium-low long term.** Maintenance risk; keep it only while it works |
| `onnxruntime-react-native` 1.24.3 | MIT; published 2026-07 | Needs a dev build; Expo config support not documented on the page checked (R8) | ~108 KB JS wrapper plus native ORT libraries | **Medium.** Good for a small exported LSTM or transformer model; extra native weight |
| `react-native-executorch` 0.10.4 | MIT; very active (published 2026-10-03) | Expo-oriented (R9); peer deps include `react-native-worklets` and download helpers | ~7.4 MB unpacked plus model files (LLMs run to hundreds of MB) | **Low for now.** Built for LLMs; too heavy for a single next-word bar; revisit for phrase expansion |

**Recommendation.**
- **Now:** reduced-motion detection with the built-in RN API. No new dependency.
- **Next native build:** `expo-haptics` ~15.0.8, opt-in.
- **Next prediction work:** strengthen the JS n-gram path, trained on a corpus whose licence is clear. Treat tfjs-react-native as legacy.
- **Later:** evaluate ONNX Runtime only if a measurable accuracy gain justifies the native size.
- **Not now:** ExecuTorch / LLMs. No change to the symbol set.
