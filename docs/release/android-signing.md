# Android signing — current source

Reviewed 2026-10-04. Android is generated by Expo prebuild; an old generated
`build.gradle` is not a persistent signing configuration. Earlier versions of
this guide described `RELEASE_STORE_*` wiring that the current clean prebuild
does not contain. Passing those properties alone does not configure signing.

`plugins/withReleaseSigningGuard.js` inspects the final release task graph.
It refuses the generated debug signing configuration for release tasks unless
`-PALLOW_DEBUG_SIGNING=true` explicitly allows a test APK. It always refuses a
debug-signed `bundleRelease`. This checks configuration; certificate inspection
of the actual artifact remains necessary. It does not establish ownership of
an arbitrary supplied key.

## Production

Use the existing EAS production profile and the owner's managed signing
credentials. Confirm the EAS project/account, upload certificate, application
ID, Play version code and track before building or submitting. The test key
is never a production credential. Run the final release/device/privacy gates
in `current-release-gates.md` before public submission.

`npm run eas:build:android:production` requests the configured app-bundle
build. This session has not verified managed credentials or produced a
production AAB. Store submission is a separate authorized action.

For a local production build, first configure the generated release signing
with the actual owner-provided keystore using a reviewed secure setup; keep
secrets outside Git and avoid passwords on a command line. The existing
project does not automatically consume `RELEASE_STORE_*` properties.

## Separate test APK

Use a clean checkout, no production Firebase configuration, and
`scripts/native-ui/make-test-identity.js` after prebuild. It consumes the
local test keystore/properties outside the repository, patches only generated
Android files, and sets a separate package and visible name. The signing guard
accepts that configured test signing for an APK; acceptance is not permission
to submit it to a store.

If the previous test key is unavailable, choose a new test identity. Never
uninstall an existing communication app to resolve a certificate conflict.
Record APK SHA-256, package/name/version/ABIs and certificate SHA-256 in the
build notes. Save extracted APKs in the owner's `OneDrive\AAC\Builds` structure.
Update `Latest` only after verification. A build/signature check is not an
installation, device, accessibility or listening test.
